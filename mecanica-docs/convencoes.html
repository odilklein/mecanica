Regras para evoluir o sistema sem quebrar o produto

Regras obrigatórias por página

// Toda página PHP:
require includes/sessao.php;      // sessão + login + CSRF + roles
require config/conexao.php;       // PDO + helpers
exigir_papel([...]);              // autorização no backend

// Todo POST mutável:
validar_csrf();

// Banco de dados:
//  - sempre prepared statements
//  - usar transação quando OS + pedido + evento + notificação mudarem juntos
//  - nunca exibir exceção PDO ao usuário (usar error_log)

// Entrada / Saída:
//  - limpar()  na entrada (trim)
//  - esc()     na saída HTML (htmlspecialchars)
//  - não confiar em preço, total, ID ou status vindos só da interface

Interface e design system

  • Usar Lucide Icons em botões e labels importantes (<i data-lucide="..."></i>).
  • Respeitar o visual de css/style.css e os componentes existentes (cards, badges de status, wizard, dynamic-list).
  • Manter botões compactos com btn-icon / action-button.
  • Telas de mecânico: operacionais e sem dados pessoais desnecessários (sem telefone/e-mail quando possível).
  • Não reintroduzir cards/telas de estoque, serviços ou agendamentos no fluxo principal sem decisão explícita de produto.

Proteção em duas camadas (roles)

  1. Sidebar: não exibir o link para quem não tem permissão.
  2. Backend: bloquear acesso direto por URL e POST com exigir_papel().

Ao adicionar uma área nova, atualizar todos os pontos do checklist abaixo.

Ocultar item no menu não é segurança. A autorização precisa existir no backend sempre.

Checklist ao adicionar funcionalidade

1. includes/sidebar.php                  -> menu por papel
2. Matriz de permissões (esta doc)       -> documento de perfis
3. Backend da página                     -> exigir_papel + validar_csrf
4. Dashboard (se houver KPI)             -> KPI/indicador novo
5. Seed SQL                              -> dados de teste do banco
6. Eventos quando o estado muda          -> os_eventos
7. Notificações aos envolvidos           -> notificar_*()
8. Preservar histórico (não apagar registros)

Checklist de teste manual

  • Testar usuário de cada perfil.
  • Testar URL direta com papel incorreto (esperar 403).
  • Testar POST sem CSRF (esperar 403).
  • Testar OS atribuída e OS não atribuída (mecânico).
  • Testar solicitação de peça do início ao recebimento.
  • Testar cliente com vários veículos e histórico.
  • Testar o seed mecanica_teste.sql em banco vazio.
  • Rodar git diff --check antes de commitar.

Resumo rápido

  • PHP procedural + PDO + Bootstrap + Lucide + JS vanilla.
  • OS é o centro do domínio.
  • Proteção sempre no backend.
  • Preparar transações ao tocar vários registros.
  • Guardar histórico, nunca apagar.
