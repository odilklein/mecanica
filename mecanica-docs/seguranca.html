Segurança

Medidas aplicadas no sistema e pontos de atenção

O que já está implementado

Sessão segura

Cookie com HttpOnly, SameSite=Lax e Secure (quando HTTPS).

CSRF token

Toda ação POST exige token CSRF (validar_csrf()), inclusive via cabeçalho X-CSRF-Token no JSON.

Autorização no backend

Cada página/rota chama exigir_papel(). Acessar URL direta com papel errado retorna 403.

Prepared statements

Toda consulta usa PDO com parâmetros — sem concatenação direta de entrada do usuário em SQL.

Anti-XSS na saída

Valores exibidos passam por esc() (htmlspecialchars) e entradas por limpar().

Senhas com hash

Sempre password_hash(); mínimo de 8 caracteres. Nunca se armazena senha em texto puro.

Upload restrito de áudio

Só data URLs de áudio; extensão validada por mapeamento, tamanho máx. 15 MB e arquivos na pasta uploads/audio.

Erros ocultos

PDO usa ERRMODE_EXCEPTION, mas exceções nunca são exibidas ao usuário — vão para error_log().

Ciclo de uma requisição protegida

Autenticação e autorização acontecem antes de qualquer conteúdo ser renderizado. Este é o caminho de cada requisição:

Exemplo de proteção em uma página

// 1. sessão + banco
require includes/sessao.php;
require config/conexao.php;

// 2. papel permitido (backend)
exigir_papel(['admin', 'secretaria']);

// 3. POST com CSRF
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    validar_csrf();
    ...
}

// 4. prepared statements
$stmt = $conn->prepare('SELECT * FROM x WHERE id = :id');
$stmt->execute([':id' => $id]);

// 5. saída escapada
echo esc($usuario['nome']);

Proteção contra manipulação de dados

  • Nunca confiar na interface: subtotais de orçamento, status, IDs relacionados e preços são recalculados/validados no servidor.
  • Transações: operações que tocam OS + pedido + evento + notificação são executadas em beginTransaction/commit/rollBack.
  • Validação de estado: mudanças de status só seguem as transições permitidas (máquina de estados).
  • Filtro de escopo: mecânico só enxerga OS com vínculo ativo (os_responsaveis).
  • Concorrência: a numeração da OS usa GET_LOCK/RELEASE_LOCK para evitar números repetidos.
  • Dados sensíveis: telefone/e-mail do cliente ficam ocultos para o perfil mecanico.
